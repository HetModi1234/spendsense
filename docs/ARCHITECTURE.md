## 2. Core Architectural Pillars

### 2.1 Deterministic Calculations vs. Generative Interpretation
Financial applications require strict numerical accuracy. LLMs are non-deterministic and must **never** be tasked with computing account balances, budget percentages, or debt splits directly.

1. **Deterministic Layer (Node.js/JavaScript)**:
   - All arithmetic, percentage calculations, date slicing, run rates, and graph reductions are performed in dedicated backend service modules (`sharedExpenseService.js`, `forecastService.js`, `duplicateDetectionService.js`, etc.).
   - Values are rounded to 2 decimal places with mathematical precision (`roundNumber()`).

2. **Generative Layer (Google Gemini API)**:
   - Gemini operates strictly on **verified summarized figures** generated by the backend.
   - Used exclusively for:
     - Natural language expense entity extraction (parsing informal text into structured JSON).
     - Interpreting verified cash flow variances into executive summaries.
     - Explaining spending velocity scenarios in plain English.
     - Conversational multi-turn reasoning via tool/function calling.

### 2.2 Gemini Tool / Function Calling Architecture
The "SpendSense AI Assistant" signature feature implements live tool calling through Google's Generative AI SDK:

```
User Query: "How much did I spend on food this month?"
      │
      ▼
Gemini Evaluates Intent & Decides to Call:
`getCategorySpending({ category: "Food" })`
      │
      ▼
Backend Context Interceptor:
- DERIVES user ID strictly from `req.user._id` (Model cannot spoof IDs).
- Queries MongoDB for user's verified Food expenses.
- Computes total: ₹6,200 across 5 transactions.
      │
      ▼
Backend sends Tool Result back to Gemini
      │
      ▼
Gemini generates natural language response + UI Card payload:
"You have spent ₹6,200 on Food this month across 5 transactions."
+ [CategorySpendingCard Component Payload]
```

### 2.3 Duplicate Detection Algorithm
The duplicate transaction detection system runs deterministically on every new expense insertion and CSV import:

1. **Temporal Proximity**: Compares candidate transaction date against existing records within a +/- 72-hour window.
2. **Monetary Match**: Checks for exact amount equality (`Math.abs(t1.amount - t2.amount) < 0.01`).
3. **Fuzzy String Similarity**: Computes Levenshtein ratio on normalized merchant names and transaction descriptions.
4. **Classification**:
   - `exact`: Date delta $\le 24$ hours AND (merchant similarity $\ge 0.8$ OR description similarity $\ge 0.8$).
   - `probable`: Date delta $\le 72$ hours AND (merchant similarity $\ge 0.6$ OR description similarity $\ge 0.6$).
5. **Non-Destructive Action**: The system **never** deletes transactions automatically. It flags them with `duplicateStatus: 'potential'` and presents actionable choices to the user: *Keep Both*, *Delete Duplicate*, or *Mark Reviewed*.

### 2.4 Debt Simplification (Splitwise-Style Roommates)
When shared expenses are logged:
1. Every member's net balance is computed:
   $$\text{Net Balance} = \sum \text{Paid} - \sum \text{Owed Share} \pm \sum \text{Settlements}$$
2. Members are bifurcated into **Creditors** ($\text{Net} > 0$) and **Debtors** ($\text{Net} < 0$).
3. A greedy matching reduction algorithm pairs the largest debtor with the largest creditor, minimizing the total number of physical money transfers required to zero out all balances.

### 2.5 Security & Data Isolation
- **Authentication**: Stateless JSON Web Tokens (JWT) signed with HMAC-SHA256 and stored in client localStorage.
- **Authorization**: All Mongoose queries (`find`, `findOne`, `deleteMany`, etc.) strictly enforce `{ userId: req.user._id }`. Cross-user data access is structurally impossible.
- **Rate Limiting**: Tiered limiters using `express-rate-limit` (General API: 300 req/15min, Auth: 30 req/15min, AI calls: 30 req/min).
- **Hardened Headers**: Configured with `helmet` for CSP, X-Frame-Options, and HSTS.
- **Zero Secret Leakage**: `client/` code contains no Gemini API keys, JWT secrets, or DB credentials. All GenAI API requests route through the backend proxy.
